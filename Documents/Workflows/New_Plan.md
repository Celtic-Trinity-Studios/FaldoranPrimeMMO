# New Plan — Chunk-Based Starter Island

**Status:** 🔵 IN PROGRESS  
**Updated:** 2026-02-10  
**Context:** The old Pillar 03 plan assumed a static UE5 Landscape. We've now replaced it with a **chunk-based procedural generation system** using ProceduralMeshComponent. This document is the new step-by-step plan to get the Starter Island running with the chunk system.

**What Changed:**
- Old approach: Manually sculpted Landscape actor, static biomes
- New approach: 64m procedural chunks, deterministic from seed, sparse change overlays
- Old files: `FPMTerrainGenerator.h/cpp` — now a legacy wrapper
- New files: `FPMChunkData`, `FPMChunkOverlay`, `FPMChunkActor`, `FPMWorldChunkManager`

---

## Step 4: Create a Chunk Terrain Material

**Goal:** A material that reads vertex colors to blend biome textures.

The chunk actors encode biome data as **vertex colors**:
| Channel | Meaning |
|---|---|
| R = 1.0 | Meadows (grass) |
| G = 1.0 | Forest (forest floor) |
| B = 1.0 | Mountain (rock) |
| A = 1.0 | Snow |
| R = 0.2 | Coast (sand) |
| R=0.5, B=0.5 | Swamp |
| All = 0 | Ocean |

### Steps:
1. Create a new Material: `Content/Materials/Landscape/M_ChunkTerrain`
2. Set up a **Vertex Color** node
3. Create 4-5 texture layers:
   - **Grass** texture → multiplied by Vertex Color R
   - **Forest Floor** texture → multiplied by Vertex Color G
   - **Rock** texture → multiplied by Vertex Color B
   - **Snow** texture → multiplied by Vertex Color A
   - **Sand** texture → use a threshold on R (R < 0.3 and R > 0.1)
4. Blend all layers additively into Base Color
5. Use the same vertex colors to drive roughness variation
6. Normal maps per layer for surface detail
7. Assign this material to the `TerrainMaterial` slot on the WorldChunkManager

> **Shortcut for prototyping:** Start with a simple material that just outputs the vertex color directly as Base Color. You'll see the biome map as colored patches (red = meadows, green = forest, blue = mountain). Replace with textured version later.

**Validation:** Material compiles in the Material Editor.

## Step 5: First Test — See the Island Generate

**Goal:** Press Play and watch chunks load around you.

1. Place a `PlayerStart` at position (0, 0, 5000) — high up so you can see the island from above
2. Make sure the default pawn is your prototype pawn or the default flying pawn
3. Press **Play in Editor (PIE)**
4. You should see:
   - Console log: `FPM: Chunk-based world system initialized`
   - Chunks progressively loading outward from your position
   - Debug boxes showing chunk boundaries (green = full, yellow = medium, red = low LOD)
   - Terrain meshes appearing with biome colors
5. Fly around — chunks should load/unload as you move
6. Open console (`~`) and try:
   - `FPM.GenerateWorld 123` — regenerates with seed 123
   - `FPM.RegenChunks` — reloads all chunks

### Troubleshooting:
| Problem | Likely Cause | Fix |
|---|---|---|
| No chunks appear | Manager can't find player position | Check PlayerStart exists, check `GetPlayerPosition()` |
| Chunks appear but no mesh | Material not assigned | Assign material on the manager |
| Flat terrain | Height not mapping to Z | Check `HeightToWorldZ()` values |
| All one biome | Noise not varying | Try different seeds |
| Huge frame hitches | Too many chunks per frame | Reduce `MaxChunksPerFrame` to 2 |

**Validation:** You can see a circular island with visible biome variation. ✅

## Step 6: Tune the Terrain

**Goal:** Make the island look like an actual island, not a math function.

Once chunks are rendering, iterate on these values in `FPMChunkData.cpp`:

### Height Tuning
| Parameter | Location | Current | Try |
|---|---|---|---|
| `MaxHeightCm` | `HeightToWorldZ()` | 30000 (300m) | 15000–40000 depending on feel |
| `SeaLevelZ` | `HeightToWorldZ()` | -2000 | Adjust to match your water plane |
| `NoiseScale` | `GenerateChunk()` | 6.0 | 4.0–10.0 (lower = smoother, higher = jagged) |
| `MeadowTarget` | `GenerateChunk()` | 0.06 | 0.04–0.10 (how flat meadows are) |

### Biome Tuning
| Parameter | Location | Current | Try |
|---|---|---|---|
| `BiomeScale1/2` | `AssignBiomeFromNoise()` | 3.5 / 5.0 | Adjust for larger/smaller biome patches |
| Biome thresholds (0.40, 0.75) | `AssignBiomeFromNoise()` | 40/35/25% split | Change for more/less of each biome |
| `IslandRadiusFraction` | `FPMChunkConstants` | 0.42 | 0.35–0.48 (island size within grid) |
| `SnowLineThreshold` | `GenerateChunk()` | 0.65 | 0.50–0.80 |

### Process:
1. Change a value in code
2. Hot reload or recompile
3. In editor console: `FPM.RegenChunks`
4. See the result immediately
5. Repeat until it looks good

**Validation:** Island has visible coastline, rising terrain inland, distinct biome patches.

## Step 7: Water Integration

**Goal:** Ocean and rivers look correct with the chunk terrain.

1. Adjust the **Water Body Ocean** Z-height to match `SeaLevelZ` from `HeightToWorldZ()`
   - Default: Z = -2000. The ocean plane should sit at this Z level.
2. Verify coast chunks (where height meets sea level) look naturally gradual
   - If the coast is too abrupt, adjust `CoastBlend` logic in `GenerateChunk()`
3. For rivers:
   - Rivers are carved into the heightmap by `RiverFactor()`
   - Optionally add a **Water Body River** actor along the carved path
   - Or defer rivers to a later pass

**Validation:** Ocean surrounds the island, coast blends into water naturally.

## Step 8: Basic Terrain Material (Textured)

**Goal:** Replace debug vertex colors with actual biome textures.

1. Upgrade the material from Step 4 with real textures:
   - Download free textures from Fab/Quixel:
     - Grass: search "grass ground" in Fab
     - Forest: search "forest floor"
     - Rock: search "cliff rock"
     - Sand: search "beach sand"
     - Snow: search "snow ground"
   - Each layer needs: Base Color, Normal, Roughness
2. In `M_ChunkTerrain`:
   - Create a `TextureSampleParameter2D` for each layer
   - Use **World Aligned** UVs (not mesh UVs) for seamless tiling across chunk boundaries
   - Blend using vertex colors as masks
   - Add a slope-based rock blend (steep slopes → rock texture regardless of biome)
3. Assign to the chunk manager

**Important:** Use **World Position** based UVs, not the mesh UV0, to avoid visible seams at chunk borders.

**Validation:** Walking across the island shows grass → forest → rock → snow transitions.

## Step 9: Foliage System (Biome-Aware)

**Goal:** Trees, grass, and rocks spawn per biome on chunk terrain.

Since we're using ProceduralMeshComponent (not Landscape), the standard UE5 foliage painting doesn't apply. Options:

### Option A: Procedural Foliage per Chunk (Recommended)
1. Create an `FPMChunkFoliageManager` that:
   - When a Full-LOD chunk loads, scatters foliage actors based on biome
   - Uses the chunk seed for deterministic placement
   - Meadows: grass clumps, wildflowers
   - Forest: trees (ISM/HISM for performance), undergrowth
   - Mountain: sparse shrubs, boulders
   - Coast: beach grass, driftwood
2. When chunk unloads, foliage is destroyed (it's regenerated from seed)

### Option B: Manual Placement (Quick Prototype)
1. Hand-place key trees and rocks in the editor
2. These become part of the handcrafted overlay layer
3. Less work now, less scalable later

**Recommendation:** Do Option B for immediate prototype, plan Option A for production.

**Validation:** Island has visible vegetation that matches biome zones.

## Step 10: Player Spawn in Meadows

**Goal:** Players spawn randomly within Meadows biome only.

1. Create `AFPMBiomeVolume` (or reuse the biome data from chunks):
   - Override `ChoosePlayerStart()` in `AFPMGameMode`
   - Query the chunk manager: `GetBiomeAtWorldPos()` for candidate spawn positions
   - Filter to only `EFPMBiome::Meadows` positions
   - Ensure spawn point is on solid ground (trace down to terrain)
   - Randomly pick from valid meadows positions
2. Place multiple `PlayerStart` actors scattered across Meadows areas as fallbacks
3. Add a **KillZ volume** under the world (Z = -10000) for fall-off protection

**Validation:** PIE with 2+ players → all spawn in Meadows area, different locations.

**Goal:** Clean up, optimize, and verify everything works together.

1. **Turn off debug visualization:** Set `bDrawDebugChunkBounds = false` on the manager

   - Open `stat fps` in console

   - If draw calls are too high, consider merging low-LOD chunks
3. **Chunk seam check:**
   - Walk across chunk boundaries — verify no visible gaps or height mismatches
   - If seams exist: chunks share edge vertices at boundaries (the +1 in 65 = 64+1)

5. **Multiplayer test:**
   - Launch PIE with 2 clients
   - Both should see the same terrain (same seed = deterministic)
   - Walk around each other, verify chunks load correctly for each
